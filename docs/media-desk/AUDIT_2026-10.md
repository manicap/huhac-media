## Gap analýza scénářů

### A. Úplně nový archiv

| Fáze | Dnes | Cíl / mezera | Failure a rollback |
|---|---|---|---|
| UI | pouze „připojit existující workspace“ | průvodce dvěma kořeny | před zápisem ukázat přesný plán |
| Backend | Media Desk žádný writer nevolá | ingest-owned init rozhraní | žádný shell s neověřenými cestami |
| Validace | vyžaduje existující manifest | storage existuje/je vhodná; workspace prázdný nebo validní | neprázdný neznámý cíl odmítnout |
| Změna stavu | žádná | stabilní ID, adresáře, veřejný prázdný katalog; jen schválené minimum | atomické kroky |
| Persistence | pouze profile TOML k existujícímu workspace | po úspěšném init uložit lokální config | při save failure workspace zůstane validní, ale není aktivní |
| Další start | funguje jen po externím ingestu | načíst nový workspace | non-ready s opravnou akcí |
| Rollback | není | odstranit jen nově vytvořené a evidované artefakty | nikdy nemaže originály/cizí adresář |

Závěr: **ABSENT**. Dnešní ingest lze podle statické analýzy spustit s prázdným
scanem a vytvoří DB/run/report/catalog; to není ekvivalent bezpečného web setupu.

### B. Existující archiv na jiném OS

| Fáze | Dnes | Cíl / mezera | Failure a rollback |
|---|---|---|---|
| UI | zadává jen workspace | samostatně zadat lokální Media Storage root | původní profil zachovat do validace |
| Backend | validuje workspace v1 | binding workspace + mapping + storage identity | žádný zápis do katalogu |
| Validace | manifest/katalog/artefakty; originál může být offline | structure + omezený SHA sample, volitelný full verify | mismatch explicitně odlišit od offline |
| Změna stavu | žádná mapping data | lokální host-specific záznam | atomic replace |
| Persistence | per-user TOML workspace | per-user mapping, ne portable workspace data | obnovit poslední validní soubor |
| Další start | cizí root → originály offline | levně ověřit binding/dostupnost | config nemazat při dočasném výpadku |
| Rollback | není třeba, katalog se nemění | odstranit/vrátit lokální mapping | previews zůstanou dostupné |

Závěr: **PARTIAL**. Workspace a preview se připojí; originály pod jiným mountem
ne. Bez full rehash lze bezpečnost zvýšit deterministickým vzorkem, ale konkrétní
politika vyžaduje schválení.

### C. Běžné opakované spuštění

| Fáze | Dnes | Mezery |
|---|---|---|
| UI/backend | profil se automaticky načte; snapshot vznikne při startu | bez hot refresh |
| Validace | resolve + veřejný contract v1 | budoucí mapping check chybí |
| Persistence | beze změny | — |
| Failure | 503 non-ready + srozumitelný stav; config se nemaže | explicitní retry může být lepší UX |
| Chybný TOML | proces skončí s chybou konfigurace před startem serveru (`src/media_desk/cli.py:28-38`) | bezpečná oprava profilu/diagnostika bez tichého ignorování |
| Změna mount path | stará cesta je `unavailable`; uživatel může validovat a uložit novou workspace cestu | pro originály chybí samostatný mapping flow |
| Rollback | není automatický zápis | ruční návrat cesty přes settings po dostupnosti |

Závěr: **IMPLEMENTED** pro dnešní jedno-workspace model.

## Nalezené rozpory a zastaralé předpoklady

1. `docs/media-desk/CONTRACT.md` se označoval za návrh před M1 a obsahoval příkaz
   vytvořit `feature/media-desk`; skutečný aktuální stav je větev `mediadesk` s
   M1.2/M1.3. Dokument je nyní prominentně označen jako historický.
2. `docs/media-desk/README.md` měl titul „M1.1“, přesto již popisoval M1.3 setup.
   Titul a navigace jsou aktualizovány bez přepsání historického kontraktu.
3. Původní kontrakt hovoří o budoucím logickém storage ID, ale kontrakt v1 dnes
   stále publikuje absolutní `source_root`. Jde o **PROPOSED**, ne implementaci.
4. Baseline mohl být čten jako důkaz, že ingest má vhodný „prázdný init“. Kód má
   pouze full ingest lifecycle; produktový init kontrakt je **ABSENT**.
5. Přítomnost SQLite WAL a locku nedokládá bezpečný multi-host NAS provoz.
6. M1.3 settings je lokální instance config, nikoli portable metadata storage ani
   storage manager.

## Testovací rozhodnutí

Audit použil static review implementace a testů. Nové pytest ani AI/regresní běhy
nebyly potřeba: dokumentace nemění runtime a sporné body (mapping, init kontrakt,
NAS semantics) nejsou dnešní testovatelnou funkcí. Historické výsledky jsou v
`STATUS.md`; nejsou vydávány za nový běh.

## Nejmenší bezpečná následující etapa

**PROPOSED S2a:** lokální read-only mapping originálů pouze v Media Desku, vázaný
na `workspace_id` a původní `source_root`, bez změny workspace, DB, ingestu a
procesorů. Přesný kontrakt, rizika a testy jsou v `SETUP_STORAGE_RFC.md`.

Před implementací S2a platí stop-gate: schválit D-011 a validační rozsah. D-012
a writer deployment mohou zůstat odložené, ale musí být schváleny před jejich
vlastními etapami.
